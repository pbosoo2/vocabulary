# 단어장 — 개인용 Notion 단어장

Notion을 원본으로 유지하고, 비밀번호 인증된 Vercel 서버만 Upstash Redis에 접근합니다. 단어·토큰을 정적 HTML, GitHub JSON 파일, URL 매개변수, 브라우저 영구 저장소에 넣지 않습니다.

## 현재 구현
- 오늘 등록 → 영어 → 일본어 → 보관 → 전체. 한국 시간 기준 날짜 필터.
- 서버에서 전체 범위 검색·필터·정렬 후 **10개씩 반환**. 이전/다음 페이지는 Notion을 호출하지 않습니다.
- 검색 대상: 단어, 한국어 뜻, 발음·읽기, 한글 발음. 영어 검색은 대소문자를 구분하지 않습니다.
- Redis는 단어별 기록/정렬 인덱스/언어·날짜 필터/문자 검색 인덱스를 저장합니다. 단어순은 정규화된 문자열 순서이며 언어별 사전의 엄밀한 가나다/가나 정렬은 아닙니다.
- 부분 문자열 검색은 문자 인덱스로 후보를 줄인 뒤 Redis 안에서 확인합니다. 흔한 한 글자 검색은 후보가 많아 비용과 실행 시간이 증가할 수 있습니다. 저장 공간·명령 수에 대한 Upstash 요금제 한도는 별도로 적용됩니다. 검증 없이 수만 개 성능을 보장하지 않습니다.
- 보관은 기존 브라우저의 ID 목록을 사용합니다. 보관 필터는 요청당 최대 2,000개 ID를 지원합니다. 다른 브라우저와 보관 목록은 동기화되지 않습니다.
- 공부 모달도 한 번에 10개를 유지하고 다음 묶음을 필요할 때 가져옵니다. Notion 학습 기록 작성은 별도이며 앱은 Notion 읽기 전용입니다.
- 갱신 정보는 기본 접힘. 최근 성공 시각과 다음 갱신 카운트다운. 모바일 메뉴 너비/간격 및 헤더 세로 가운데 정렬 유지.

## 동기화 버튼
- **동기화**: 초기 저장 이후 추가·수정된 단어와 학습 기록만 확인합니다. 이 버튼은 주간 전체 목록 대조를 새로 시작하지 않습니다.
- **전체 동기화**: 수정 날짜와 관계없이 모든 단어/학습 기록을 다시 가져오고, 삭제·보관·원본 밖으로 이동한 항목도 목록 대조로 정리합니다. Redis에서 빠진 단어를 원본으로부터 다시 저장할 때 사용합니다. Notion 원본은 삭제하거나 수정하지 않습니다.
- 다른 작업이 진행 중이면 전체 동기화 요청은 예약되어 현재 작업 뒤에 실행됩니다. 진행 중인 전체 작업은 중복 실행하지 않습니다.
- 두 버튼 모두 성공 완료 후 다음 자동 동기화는 1시간 뒤입니다.
- 기존 자동 동기화의 주 1회 목록 대조는 유지합니다.

## 저장과 동기화
1. 처음 사용할 때 기존 단어/학습 기록을 가져와 서버 저장소에 저장합니다.
2. 이후 마지막 성공 동기화 시작 시각부터 변경된 단어와 학습 기록만 조회합니다. API 반영 지연을 줄이기 위해 2분 겹침 구간을 다시 조회하고 같은 ID를 갱신합니다.
3. 학습 기록의 단어 연결이 바뀌면 이전/새 단어의 롤업 정보를 모두 다시 확인합니다. 많은 관계의 롤업은 Notion 속성 페이지네이션을 추가 조회합니다.
4. 삭제/보관/원본 밖으로 이동한 페이지는 수정 날짜 조회에 잡히지 않을 수 있어, **주 1회 동기화에서 전체 목록을 대조**합니다. 이때는 변경 없는 목록도 조회합니다. 삭제는 그 전까지 지연될 수 있습니다. 원본 DB 접근 오류나 불완전한 조회를 삭제의 증거로 처리하지 않습니다.
5. 긴 동기화는 약 35초 단위의 재개 가능한 작업으로 나눕니다. Redis에 커서와 진행 상태를 저장하고 열린 화면이 이어서 처리합니다. 작업당 1만 개 제한은 없습니다. 아주 큰 롤업 하나가 요청 시간 내에 처리되지 못하면 재시도가 필요할 수 있습니다.
6. 분산 잠금으로 여러 탭의 중복 동기화를 막습니다. 실패 시 마지막 성공 시각/워터마크는 유지하고 자동 재시도는 1시간 뒤로 미룹니다. 중간에 적용된 개별 단어가 먼저 보일 수 있으므로 전체 작업의 원자적 스냅샷은 아닙니다.
7. **화면 새로고침은 Upstash 조회만 수행**합니다. 최초 저장, 진행 중 작업 재개, 기한 경과, 동기화 버튼만 Notion 작업을 시작/재개합니다. 이미 시작한 작업을 재개하는 것은 신규 전체 조회가 아닙니다.
8. 성공 완료 후 다음 자동 동기화는 1시간 뒤. 자동 동기화는 **로그인한 화면이 열려 있을 때** 작동합니다. 닫힌 상태에서는 백그라운드 예약 작업을 실행하지 않습니다. 이 앱에는 Cron/QStash가 없습니다.
9. 이전 전체 단어의 AES-GCM 브라우저 캐시는 로그인 시 제거합니다. 현재 단어는 메모리에만 유지하며 영구 저장은 Redis에서 수행합니다.

## Vercel 환경 변수
값은 사용자가 직접 Vercel에 입력합니다. 채팅이나 GitHub에 보내지 마세요. Production에 연결하고 재배포하세요.

| 변수 | 역할 |
|---|---|
| `APP_PASSWORD` | 최소 8자, 무작위 16자 이상 권장 |
| `SESSION_SECRET` | 별도 무작위 32자 이상 |
| `NOTION_TOKEN` | 내부 연결 Read content 토큰 |
| `KV_REST_API_URL` | Upstash REST HTTPS 엔드포인트 |
| `KV_REST_API_TOKEN` | 읽기·쓰기 가능한 표준 토큰 |

`KV_REST_API_READ_ONLY_TOKEN`, `KV_URL`, `REDIS_URL`은 이 앱에서 사용하지 않습니다. 읽기 전용 토큰도 프런트엔드에 노출하지 않습니다. 기존 Upstash 이름 `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`도 서버에서 지원합니다.

선택 변수:
- `NOTION_DATA_SOURCE_ID`: 기본 `3f7551f3-818b-8095-93b4-000bc45e4202`.
- `NOTION_LEARNING_DATA_SOURCE_ID`: 기본 `21cd8aef-3b88-4af4-9b38-f095c61d3130`.

원본 단어/학습 기록 DB 모두 Notion 연결의 Content access에 포함해야 합니다. 연결된 보기만 공유하지 마세요. `한글 발음`은 선택 텍스트 속성이며 없으면 미등록으로 표시합니다. 등록 날짜를 생성 날짜로 임의 대체하지 않습니다.

## 배포 / 보안
- GitHub main → Vercel 재배포. Framework Preset Other, 서버 함수가 포함된 배포.
- `/api/words` GET/POST: 인증된 Redis 페이지 조회. `/api/sync` POST: 인증 + 같은 출처 + JSON 요청만 허용.
- 응답은 private/no-store. 실제 단어는 로그인 전 반환하지 않습니다. Redis 자격 증명은 서버 환경 변수에만 있습니다.
- 7일 서명 세션 쿠키: `__Host-vocabulary-v2`, HttpOnly/Secure/SameSite=None/Partitioned. 비밀번호/세션 키 변경 후 재배포 시 기존 세션 무효화.
- 실패 횟수 제한은 인스턴스별 보조 제한. Vercel Firewall 추가 제한 권장.
- Redis 저장 내용은 인증된 서버/저장소 관리자에게 읽을 수 있는 데이터입니다. 앱 수준의 Redis 데이터 암호화는 구현하지 않았습니다. Vercel/Upstash 관리자도 신뢰 범위에 포함됩니다.
- 데이터에는 만료 시간을 두지 않습니다. 임시 검색 키만 60초 TTL. **Eviction 꺼두기**를 권장합니다. 용량/요금제 한도 초과를 오류로 처리하고 원본은 Notion에 유지합니다.

## Notion 임베드
Notion에서 `/임베드` → `https://vocabulary-five-beryl.vercel.app/`. Notion 안에서 별도 로그인할 수 있습니다. CSP는 notion.so/notion.com 및 하위 도메인만 허용합니다. 임의 공개 사이트 커스텀 도메인은 별도 설정이 필요합니다. 쿠키를 막는 환경에서는 브라우저 열기 링크를 이용하세요. 로그인 요구를 제거하거나 URL에 토큰을 넣지 않습니다.

## 테스트
`npm test`: 인증/세션/매핑, 로컬 Redis를 이용한 10개 페이지 조회·검색·정렬·변경분·학습 연결 변경·삭제 확인·실패 보존 테스트.
Redis 통합 테스트는 선택적으로 Python `fakeredis[lua]`를 설치한 개발 환경에서 실행되며, 없으면 해당 테스트만 skip합니다. 실제 운영 인증 정보를 사용하지 않습니다.
운영 Upstash/Notion 접근 권한은 배포 후 로그인한 화면에서 검증해야 합니다. 브라우저 테스트와 로컬 Redis 테스트 성공이 실제 토큰의 유효성을 증명하지는 않습니다.

## 발음 파일 재생
- Notion `발음 파일` 파일 속성(고정 속성 ID `^iVU`)에 MP3/M4A/WAV 등 음성 파일을 추가합니다. 파일이 없는 단어에는 재생 UI가 없습니다.
- 카드와 한 장씩 공부하기에서 `발음 듣기`를 누르면 재생합니다. 퀴즈에서는 정답 확인 후에만 재생 UI를 보여 주어 답이 미리 노출되지 않도록 합니다. 여러 파일은 선택 목록을 제공합니다.
- 이 기능 최초 배포 뒤 기존 파일을 인식하려면 **전체 동기화 한 번**을 실행합니다. 이후 파일 추가/삭제는 일반 변경분 동기화에 포함됩니다.
- Redis에는 `hasAudio` 여부만 저장합니다. 파일 바이트나 만료되는 Notion 다운로드 URL은 저장하지 않습니다.
- `/api/audio` POST는 로그인·같은 출처·JSON·원본 데이터 소스 소속·미삭제 페이지를 확인하고, 해당 단어 하나의 최신 파일 주소를 반환합니다. 목록 전체를 동기화하지 않으며 Notion/Redis에 쓰지 않습니다.
- 오디오 자체는 브라우저가 원본 HTTPS 파일 주소에서 재생합니다. 서버가 파일을 프록시하지 않습니다. 새로운 환경 변수는 필요하지 않습니다.
- 재생은 사용자가 눌러 시작합니다. 임베드/모바일 브라우저가 자동 시작을 차단하면 표시된 오디오 컨트롤의 재생 버튼을 한 번 더 누릅니다. 화면 전환·로그아웃·팝업 닫기 시 재생을 중단합니다.
